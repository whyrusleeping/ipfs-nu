## Codebase gotchas
- 2026-10-22 [measured observation] Interrupted NAT-lab daemon tests can leave orphaned `nu daemon`/`nu relay` processes under /tmp/TestDaemonNAT*; check with `pgrep -x nu -a` (not `pkill -f`, which can match the calling shell) before manual multi-daemon runs on default ports. <!-- ycc-memory id=m-dmb4qxogarqe kind=observation session=s_ce5d367a91139809 event=130 actor=coordinator scope=workspace classified=model -->
- 2026-10-22 [measured observation] alphac-1/2 have Realtek r8169 NICs without UDP segmentation offload (alphac-3 has an Intel E810 with it); quic-go GSO halves send throughput there, so Nu's swarm.gso=auto disables it—check `UDP GSO` in daemon logs when comparing benchmarks. <!-- ycc-memory id=m-dmbo2u4iqnia kind=observation session=s_ce5d367a91139809 event=790 actor=coordinator scope=workspace classified=model -->
- 2026-10-26 [measured observation] fil.pub pubs (UnixFS dirs stored on Filecoin PDP providers) are announced to IPNI only as HTTP trustless-gateway providers, not Bitswap, so `nu import ipfs <cid>` finds no providers; it works offline from a CAR fetched from a provider (`Accept: application/vnd.ipld.car` on e.g. mainnet-pdp.infrafolio.com/ipfs/<cid>). Signed pubs put a protobuf field 1001 inside the root UnixFS Data, and bridge/unixfs.go rejects unknown fields. <!-- ycc-memory id=m-dmeheqj508lj kind=observation session=s_4bba32efa04aceb9 event=116 actor=coordinator scope=workspace classified=model -->
- 2026-10-26 [measured observation] Since 0086, `nu import ipfs <cid>` also fetches from HTTP trustless gateways found via ipfs.routing_url (default cid.contact), so Filecoin/fil.pub content imports without a CAR; node package tests force IPFSRouting="off" so they never hit the network. <!-- ycc-memory id=m-dmei3eeivbiq kind=observation session=s_4bba32efa04aceb9 event=458 actor=coordinator scope=workspace classified=model supersedes=m-dmeheqj508lj -->
- 2026-10-29 [measured observation] On the dev host (192 cores, 13 multicast interfaces incl. docker bridges), loopback `nu get` caps at ~85 MB/s because swarm.gso=auto disables GSO from the default-route NIC (eno1np0), so use alphac for network throughput and the dev host only for Nu-side CPU profiles. <!-- ycc-memory id=m-dmh1xxwyr1a3 kind=observation session=s_05bc7c0412573b4e event=601 actor=coordinator scope=workspace classified=model -->
